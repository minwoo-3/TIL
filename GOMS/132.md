# Spring MVC 클라이언트 오류 예외 4xx 응답 처리

## 어떤 문제?

GlobalExceptionHandler의 @ExceptionHandler(Exception::class)가 Spring MVC가 원래 4xx로 응답하는 예외까지 500으로 바꿈

- 존재하지 않는 경로: NoResourceFoundException → 500 (원래 404)
- 지원하지 않는 method: HttpRequestMethodNotSupportedException → 500 (원래 405)
- 지원하지 않는 Content-Type: HttpMediaTypeNotSupportedException → 500 (원래 415)
- multipart 크기 초과: MaxUploadSizeExceededException → 500 (원래 413)

위와 같이 Spring MVC가 반환해주는 잘못된 요청 등에 대한 에러를 500으로 바꿈

### 왜?

이 예외들을 받는 handler가 GlobalExceptionHandler에 없었음
그래서 맨 끝에 있는 catch-all로 가서 이렇게 됨 → 종류 상관없이 500, ERROR 로그 + stack trace로 처리

## 우려되는 상황

- 잘못된 오류가 올 시 원인 파악이 어려워짐 앱에서 잘못 보낸 것에 대한 오류면 더더욱
- 서버 장애가 묻힐수 있음
- 로그에 불필요한 FCM이 쌓여버림

## 어떻게 해결?

Spring 예외를 받는 전용 handler를 추가함

```@ExceptionHandler(
        NoResourceFoundException::class,
        NoHandlerFoundException::class
    )
    fun handleNotFoundException(
        e: Exception,
        request: HttpServletRequest
    ): ResponseEntity<ErrorResponse> {
        return clientErrorResponse(e, ErrorCode.NOT_FOUND_RESOURCE, request)
    }

    @ExceptionHandler(HttpRequestMethodNotSupportedException::class)
    fun handleMethodNotSupportedException(
        e: HttpRequestMethodNotSupportedException,
        request: HttpServletRequest
    ): ResponseEntity<ErrorResponse> {
        return clientErrorResponse(e, ErrorCode.METHOD_NOT_ALLOWED, request)
    }

    @ExceptionHandler(HttpMediaTypeNotSupportedException::class)
    fun handleMediaTypeNotSupportedException(
        e: HttpMediaTypeNotSupportedException,
        request: HttpServletRequest
    ): ResponseEntity<ErrorResponse> {
        return clientErrorResponse(e, ErrorCode.UNSUPPORTED_MEDIA_TYPE, request)
    }

    @ExceptionHandler(MaxUploadSizeExceededException::class)
    fun handleMaxUploadSizeExceededException(
        e: MaxUploadSizeExceededException,
        request: HttpServletRequest
    ): ResponseEntity<ErrorResponse> {
        return clientErrorResponse(e, ErrorCode.PAYLOAD_TOO_LARGE, request)
    }
```
