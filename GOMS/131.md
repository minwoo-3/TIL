# 만료·위조 Refresh Token 재발급·로그아웃 401 응답 처리

## 어떤 문제?

Refresh Token이 만료되었거나 형식이 잘못된 경우
`PATCH /api/v3/auth/reissue`(토큰 재발급)가 401이 아닌 500으로 응답

쉽게 말해 refresh token이 만료되거나 위조 됐을때 `PATCH /api/v3/auth/reissue`과 `DELETE /auth/signout`가 4XX가 아니라 5XX를 반환

## 우려되는 상황

오래동안 앱을 사용하지 않는 사용자가 refresh token과 access token <br>
모두 만료가되면 원랜 401(access 만료)를 앱이 API로부터 받고 reissue를 호출하고<br>
refresh token도 만료된걸 보고 reissue가 401을 다시 줘서<br>
'다시 로그인 하세요'가 떠야하는데
500을 반환해 줘서 오류 화면에 갇히는 상황이 발생 할 수 있음

## 어떻게 해결?

reissue가 refresh token 검사를 실패하면 401 에러를 반환하게 함

### 고치기 전

- refresh 토큰을 `parseClaims()` 검사 했을때 jjwt 실패를 아무도 받지 않음 -> 서버문제가 아닌데 5XX가 나옴

### 해결

- RefreshTokenClaimsParser에서 이 예외를 받아 INVALID_REFRESH_TOKEN(401)으로 바꿈
- 만료, 위조, 형식 오류가 모두 해당
- 이제 refresh token 만료된 사람은 '다시 로그인 하세요'로 넘어감

## 느낀점

예외처리 코드를 중요하다고 생각한 적이 없어서 대충 AI한테 전부 맡기고 확인 안한 경우가 많았는데 우려상황도 찾아보고 문제도 찾아보니 생각보다 더 중요하다는 것을 느꼈다
