# MSA
- MicroService Architecture

- 작고 독립적으로 배포 가능한 각각의 기능을 수행하는 서비스로 구성된 프레임워크 

## MSA 등장 배경
- Monolithic Architecture의 한계 보안을 위해 등장

- 물리적인 서버를 사용하는 방식(Monolithic Architecture) on-promise(IT 인프라를 클라우드가 아닌 사내 전산실이나 자체 데이터센터에 직접 구축하고 운영하는 방식)가 아닌 클라우드 환경으로 서버를 구성하는 방식(MSA)으로 바뀜

### Monolithic Architecture
- 소프트웨어의 모든 구성요소가 한 프로젝트에 통합되어 있는 형태

- 예시로 개발을 위해 모듈별로 개발하고 완료된것을 웹 하나로 배포

- 주로 소규모 프로젝트에 활용

#### 한계점
- 부분 장애가 서비스 전체로 확대될 수 있음

- 사용되지 않는 모든 서비스가 Scale-out되어야 하기 때문데 부분 Scale-out이 어려움

- 여러 컴포넌트가 강하게 하나로 연결되어 있어서 수정이나 변경이 어렵다

- 많은 사람이 하나의 시스템을 개발하여 배포하기 때문에 배포 시간이 오래 걸린다

- 한 프레임워크와 언어에 종속적이다

## MSA 특징
- SOA(Service Oriented Architecture)
    - 소프트웨어 기능을 서비스로 쪼개고 그 서비스를 필요할 때만 불러서 쓰자는 설계
    - DB나 내부 로직은 가리고 API로만 소통하기 때문에 사용
    - 기술 중립적 프로토콜로 소통하여 다양한 언어 사용 가능
    - REST나 Kafka 같은 가벼운 방식 사용
    - 서비스는 하나의 기능만 수행하여 다른 기능에 간섭 하지 않음

### 장점
- RCP, Message-driven API등의 방식으로 통신해서 서비스 개발이 빠르게 하고 유지보수도 쉬워진다

- 여러 기술 스택을 사용할 수 있다

- 서비스 별로 따로 배포할 수 있어서 CD를 갑벼고 빠르게 할 수 있다

- 득정 기능에 부하가 돌때 그 기능만 컴퓨터를 늘리는 Scale-out을 하면 되서 메모리와 CPU 이득이 크다

### 단점
- 모놀리식에 비해 복잡도가 높고 트랜잭션 설게가 어렵다

- 비지니스에 대한 DB를 가지고 있는 서비스가 각기 달라서 트랜잭션 유지보수가 어렵다

- 개발 환경과 운영 환경이 다 달라서 통합테스트가 어렵다

- 실제 운영 환경에서 배포가 어렵다
