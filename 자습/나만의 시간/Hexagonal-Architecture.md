# Hexagonal Architecture(헥사고날 아키텍처)

## 클린 아키텍처
- 비즈니스 규칙이 외부로부터 독립적으로 만들어 테스트를 용이하게 함
- 도메인 코드가 바깥으로 향하는 어떠한 의존성도 없어야 함
- 도메인은 어떤 영속성 프레임워크가 사용되는지 알 수 없음
- 영속성 계층이 도메인 계층에 의존하고, 영속성 엔티티를 도메인 엔티티로 변환하는 과정 필요
- 도메인 밖에는 유스케이스가 있고, 이는 단일 책임을 갖기 위해 조금 더 세분화 되어 있음

## 헥사고날 아키텍처
- 클린 아키텍처를 일반화한 구조 중 하나
- 어댑터와 포트를 중심으로 구성 (포트와 어댑터 아키텍처)
- 핵심 비즈니스 로직은 중앙의 도메인에 위치, 포트와 어댑터로 외부와 소통
- 도메인 로직과 인프라 스트럭처 계층을 명확히 분리함으로써 변경사항이 도메인 로직에 미치는 영향 줄임
